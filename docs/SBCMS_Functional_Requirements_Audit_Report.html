2. System Architecture & Verification Methodology

2.1 Technical Stack Overview

The SBCMS platform is structured as a modern decoupled full-stack web application designed for campus cafeteria operations:

  • Frontend Architecture: Single Page Application (SPA) built on React 18, Vite bundling, React Router v6 navigation, and context-driven state managers:
    • AuthContext: Handles user identity, roles (student, faculty, officer, staff, manager, admin), and token persistence.
    • CartContext: Enforces single-cafeteria cart isolation, stock checks, and prep time estimation.
    • OrderContext: Manages order tracking, status transitions, Web Audio API sound chime notifications, and live polling.
    • ToastContext: High-visibility user feedback alerts across all pages.
  • Backend Architecture: RESTful micro-service built on Node.js and Express:
    • authController.js: Multi-role authentication, credential hashing, OTP issuance, and 15-minute brute-force lockout.
    • orderController.js: Atomic stock verification, token generation, FIFO sorting, pickup validation, and refund processing.
    • menuController.js & canteenAccessMiddleware.js: Multi-tenant cafeteria isolation ensuring staff can only modify their assigned kitchen.
    • analyticsController.js: Revenue calculation, peak hour distribution, and cross-cafeteria reports.
  • Real-Time Synchronization Engine: Dual-layer real-time mechanism combining Web BroadcastChannel (instant cross-tab updates without page reload) with resilient HTTP polling (4–5 second interval), well exceeding the mandatory 10-second SLA.

2.2 Audit Methodology

Each requirement from Section 5.1 was evaluated using a four-step verification protocol:

  1. Requirement Extraction: Exact requirement statement, priority classification, and acceptance criteria mapped from the RAD PDF.
  2. Static Code AST & Symbol Inspection: Locating the underlying controllers, data models, routes, and UI components implementing the business logic.
  3. State & Rule Validation: Verifying boundary conditions (e.g., 5 failed login attempts triggering 15-minute lockout; single-cafeteria cart enforcement; stock auto-zeroing).
  4. Live Workflow Execution: End-to-end tracing from customer ordering, payment gateway simulation, token generation, kitchen KDS handling, to pickup verification.

4. Discrepancy Analysis & Refinement Actions

Refinement Item 1: FR-05 Guest Pass Expiration Window

Requirement Statement: "The system shall allow a visitor to create a guest account using a full name and email address, which shall expire after 24 hours unless re-verified."

Current Code State: In backend/server/models/Guest.js (line 4), the expiration constant is configured as:

// Current code: const SEVEN_DAYS_MS = 7 * 24 * 60 * 60 * 1000;

Recommended Refinement: Adjust the constant and method to enforce the exact 24-hour window specified in the RAD document:

// Aligned code for FR-05: const TWENTY_FOUR_HOURS_MS = 24 * 60 * 60 * 1000; export function activateGuest(id) { const guest = findGuestById(id); if (!guest) return null; guest.verified = true; guest.status = "active"; guest.expiresAt = new Date(Date.now() + TWENTY_FOUR_HOURS_MS).toISOString(); return guest; }
Refinement Item 2: FR-17 Outbound Email on Ready Status (Optional)

Requirement Statement: "The system may send an SMS or email notification to the user when the order status changes to Ready." (Optional Priority)

Current Code State: The system currently implements FR-16 (In-app audio chime + toast notification). The email delivery mechanism is fully present in backend/server/utils/sendOTP.js utilizing Nodemailer SMTP, but is currently scoped to registration and login verification OTPs.

Recommended Refinement (If Desired): Trigger an email dispatch inside backend/server/controllers/orderController.js when status transitions to "ready":

if (status === "ready" && targetUser?.email) { sendEmailNotification( targetUser.email, `Order #${updated.tokenNumber} is Ready!`, `Your hot meal is ready for collection at ${updated.pickupCounter}.` ).catch(err => console.warn("Email notify failed:", err)); }
